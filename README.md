# 코드온 부스 안내 (CODE:ON)

2026학년도 동아리 발표회 코드온 부스용 웹앱입니다.
직접 학습시킨 신경망 챗봇과 3D 컴퓨터실 지도가 한 화면에서 함께 움직입니다.

## 실행

`index.html` 을 더블클릭합니다. 설치도 인터넷도 필요 없습니다. (Chrome 또는 Edge 권장)

## 폴더 구성

| 파일 | 하는 일 |
|---|---|
| `index.html` | 화면 뼈대 |
| `css/style.css` | 화면 꾸밈 |
| `js/data.js` | 행사, 좌석 구역, 팀 소개, 자리 배정 **(내용을 고칠 때 여는 파일)** |
| `js/store.js` | 브라우저에 저장하기, 비밀번호 해시(SHA-256) |
| `js/intents.js` | 챗봇 학습 자료: 의도별 질문 예시 |
| `js/nlp.js` | 자연어 처리: 개체 찾기, 글자 조각 특징, 신경망 계산 |
| `js/chatbot.js` | 의도에 맞는 답 만들기 |
| `js/model.js` | 학습된 신경망 가중치 (자동 생성, 직접 고치지 않음) |
| `js/map3d.js` | 3D 컴퓨터실 지도 |
| `js/app.js` | 채팅창, 안내 창, 관리자 창, 인기도, 피드백 등 화면 연결 |
| `train.js` | 신경망 학습 스크립트 |
| `tests/questions.js` | 챗봇 시험 문제 (학습에 쓰지 않는 질문과 정답) |

## 자주 하는 수정

**팀 소개 문구 고치기**: `js/data.js` 의 `teams` 에서 `desc`, `how` 를 고치고 새로고침(F5).
지금 문구는 계획서의 주제만 보고 적은 임시 문구입니다.

**자리 배정 바꾸기**: 화면 오른쪽 위 `관리자` 버튼 (또는 Ctrl + Shift + E) → 로그인 → `자리 배정` 탭.

**포토부스 사진 틀 바꾸기**: `assets/photo` 폴더의 그림을 같은 이름으로 바꾸거나, `js/data.js` 의 `photoFrames` 에 줄을 추가합니다.

**1부 → 2부 자동 전환**: `js/data.js` 의 `partSwitchTime` 에 교대 시각을 `"10:30"` 처럼 적습니다.
행사 날짜(12월 24일)에만 동작합니다. 비워 두면 화면의 1부/2부 버튼으로 바꿉니다.

**챗봇이 못 알아듣는 질문 가르치기**
1. `관리자` → `피드백` 탭에서 `학습 자료용으로 복사` 를 누릅니다. (틀렸다고 표시된 답과 못 알아들은 질문이 담깁니다)
2. 그 질문을 `js/intents.js` 의 알맞은 의도에 예시로 추가합니다.
3. 터미널에서 `node train.js` 를 실행합니다. (외부 패키지 없음, 약 20초)
4. 새로고침하면 새 모델이 적용됩니다.

팀의 `aliases`(다르게 부르는 이름)를 고쳤을 때도 `node train.js` 를 한 번 실행하세요.

**자동 초기화 시간**: `js/app.js` 맨 위 `IDLE_RESET_MS` (기본 2분, 0 이면 끔).

## 관리자 기능

기본 비밀번호는 `codeon2026` 입니다. **처음 로그인하면 `설정` 탭에서 바로 바꾸세요.**

| 탭 | 하는 일 |
|---|---|
| 자리 배정 | 체험 A~D 자리(1부, 2부)와 뒷벽 전시 1~4의 팀 바꾸기, 배정 확정 표시 |
| 인기도 · 방문 인원 | 방문 인원수(지도에 걸어 다니는 모형 수, 0~80), 팀별 인기도 직접 설정 |
| 피드백 | 방문자가 남긴 "도움 됐어요 / 틀렸어요", 못 알아들은 질문 모아 보기와 내보내기 |
| 설정 | 비밀번호 바꾸기, 설정 코드 복사·적용, 관리자 버튼 숨기기 |

**인기도**: 기본값은 챗봇에서 그 팀이 검색된 횟수 + 지도·안내 창에서 눌린 횟수입니다.
관리자가 0~100을 직접 적으면 그 값을 씁니다. 인기도가 높은 부스에 방문자 모형이 더 자주 들르고,
상위 3팀에는 지도 이름표에 "인기" 표시가 붙으며, 챗봇의 추천 답에도 반영됩니다.

**방문자 모형**: 입구로 들어와 도장판을 받고, 부스 몇 곳을 들른 뒤 출구로 나갑니다.
지도를 만지는 동안에는 흐려져서 가리지 않고, 3~4초 가만히 두면 다시 선명해집니다.

**혼잡도와 관람 동선**: 혼잡도는 관리자가 정한 방문 인원수로 판단합니다. (기준은 `js/data.js` 의 `congestion`)

| 혼잡도 | 기준(기본값) | 추천 동선 |
|---|---|---|
| 혼잡 | 35명 이상 | 빠른 동선 (4곳): 입구 → 한산한 체험 1팀 → 진로 1분야 → 출구 |
| 보통 | 15~34명 | 기본 동선 (6곳): 입구 → 인기 체험 2팀 → 진로 1분야 → 전시 1팀 → 출구 |
| 여유 | 15명 미만 | 골고루 즐기는 동선 (9곳): 입구 → 인기 체험 3팀 → 포토부스 → 전시 1팀 → 진로 2분야 → 출구 |
| (직접 선택) | | 도장 완성 동선 (9곳): 입구 → 체험 4팀 → 진로 3분야 → 출구 |

들르는 곳은 입구와 출구를 포함해 4~9곳입니다. 진로 전시는 "웹 개발"처럼 분야 이름으로 나옵니다.
길은 오른쪽 안쪽 통로로 내려가 27·28번과 33·34번 책상 사이 복도를 건넌 뒤, 왼쪽 안쪽 통로로 올라가 진로 전시를 보고,
벽 쪽 통로로 내려가 출구로 가는 한 방향 흐름입니다. 33·34번 뒤쪽은 포토부스나 전시를 볼 때만 지나갑니다.
챗봇에는 조건을 붙여 물을 수 있습니다: "치동고 인재들 포함한 동선", "게임 위주 동선", "AI 보안도 들르는 동선",
"포토부스 넣어서", "6곳만 도는 동선", "빨리 도는 동선", "도장 다 모으는 동선".
예상 시간은 `congestion.minutes` 의 어림값으로 계산하며 기다리는 시간은 넣지 않습니다.
혼잡도는 실제 인원을 세는 것이 아니라 관리자가 입력한 숫자이므로, 당일에는 입구 담당이 보이는 대로 숫자를 고쳐 주어야 맞습니다.

**서버가 없어서 생기는 한계 (중요)**
- 설정, 검색 횟수, 피드백은 **그 컴퓨터의 그 브라우저에만** 저장됩니다. 방문자 폰에서 남긴 피드백은 그 폰에만 남습니다.
- 다른 컴퓨터로 옮기거나 인터넷에 올린 사이트의 모든 방문자에게 적용하려면, `설정` 탭의 설정 코드를 복사해
  `js/data.js` 의 `var saved = null;` 에서 `null` 자리에 붙여넣고 다시 올립니다.
- 관리자 잠금은 부스 PC에서 방문자가 설정을 건드리지 못하게 막는 용도입니다. 코드가 전부 브라우저에 있어서
  작정한 사람까지 막는 보안은 아닙니다. 다만 누가 뚫어도 바뀌는 것은 그 사람 화면뿐입니다.
- 인터넷에 올릴 때는 비밀번호를 바꾼 설정 코드를 `saved` 에 넣고, 이 문서의 기본 비밀번호 줄은 지우세요.

## 챗봇이 답하는 과정

1. 개체 찾기: 팀 이름, 진로 분야, 주제어를 찾아 기호(Ⓣ Ⓕ Ⓖ)로 바꿉니다. 자모 단위 비교로 오타도 어느 정도 잡습니다.
2. 특징 추출: 문장을 글자 1~3개짜리 조각(n-gram)으로 쪼개 숫자 벡터로 만듭니다.
3. 신경망: 입력 → 은닉층 64 → 은닉층 32 → 의도 35개의 확률(softmax). Adam, 드롭아웃으로 학습했습니다.
4. 개체 보정: 팀 이름이 없는데 "팀 위치" 의도가 나오면 낮추는 식으로 확률을 맞춥니다.
5. 확신도가 42%보다 낮으면 "배우지 않은 내용"이라고 답하고 그 질문을 기록합니다.

## 노트북에서 느릴 때

Windows 설정 → 시스템 → 디스플레이 → 그래픽에서 브라우저를 "고성능(외장 그래픽)"으로 지정하고 전원을 연결하세요.
계속 느리면 앱이 스스로 그림자를 끄고 해상도를 낮춥니다.
